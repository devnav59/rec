# دیدبان عدد صفحه / Screen Number Watcher

یک اپلیکیشن اندروید برای پیدا کردن یک نشانه روی صفحه، خواندن عدد نزدیک آن و اعلام تغییرِ عدد است. برنامه به‌صورت یک پنجرهٔ شناور کوچک باقی می‌ماند تا بتوان آن را جابه‌جا، بی‌صدا یا متوقف کرد.

> **حریم خصوصی:** پایش فقط بعد از تأیید گفت‌وگوی رسمی Screen Capture اندروید شروع می‌شود. فریم‌ها در حافظه و روی همان دستگاه پردازش می‌شوند؛ برنامه فریم‌ها را ذخیره، ارسال یا ضبط نمی‌کند. هنگام اجرا یک سرویس پیش‌زمینه، اعلان دائمی (با توجه به تنظیم اعلان سیستم) و دکمهٔ توقف در پنجرهٔ شناور وجود دارد.

## قابلیت‌ها

- **نشانهٔ متنی / نماد قابل‌خواندن:** متن یا نماد کوتاهی مثل `HP` را وارد کنید. OCR در هر فریم مکان فعلی آن را پیدا می‌کند، بنابراین با جابه‌جا شدن نشانگر روی صفحه نیز عدد دنبال می‌شود.
- **نشانهٔ تصویری:** برای یک آیکون یا علامت گرافیکی، یک تصویرِ برش‌خورده از خود نماد انتخاب کنید. تطبیق الگوی محلی، مکان آن را پیدا می‌کند؛ سپس OCR عدد اطراف آن را می‌خواند. تصویر باید برش نزدیک و تقریباً هم‌اندازهٔ نماد روی صفحه باشد.
- انتخاب جای عدد نسبت به نشانه: راست، چپ، بالا، پایین یا نزدیک‌ترین عدد.
- پشتیبانی از ارقام فارسی و عربی در **مقایسه و اعلام** عدد (برای نمونه `۱۲٬۳۴۵٫۶` به شکل پایدار `12345.6` تشخیص داده می‌شود).
- فیلتر پایداری: مقدار تازه باید در دو اسکن پیاپی دیده شود؛ این کار اعلام‌های اشتباهِ تک‌فریم OCR را کم می‌کند.
- گفتار فارسی در صورت وجود موتور گفتار فارسی روی دستگاه؛ در غیر این صورت از زبان پیش‌فرض دستگاه استفاده می‌شود.
- بدون روت و بدون Accessibility Service. فقط مجوزهای شفاف Overlay، MediaProjection و اعلان درخواست می‌شوند.

## استفاده در گوشی

1. پروژه را نصب کنید و **اجازهٔ پنجرهٔ شناور** را بدهید.
2. روش پیدا کردن نشانه را انتخاب کنید:
   - **متن / نماد OCR:** متن نشانه را وارد کنید. برای آیکون‌های غیرقابل‌خواندن، برچسب متنی نزدیک آن را وارد کنید.
   - **تصویر نماد:** یک عکس برش‌خورده از نماد انتخاب کنید. بهترین نتیجه با برش گرفته‌شده از اسکرین‌شات همان دستگاه و در همان مقیاس حاصل می‌شود.
3. محل عدد را نسبت به نشانه و فاصلهٔ اسکن را مشخص کنید.
4. روی «شروع پایش» بزنید و گفت‌وگوی رسمی اشتراک‌گذاری صفحهٔ اندروید را تأیید کنید.
5. پنجرهٔ شناور را از دستهٔ `◉` جابه‌جا کنید. `🔊/🔇` گفتار را تغییر می‌دهد و `×` پایش را متوقف می‌کند.

اولین عدد به‌صورت پیش‌فرض فقط نمایش داده می‌شود؛ گزینهٔ «اولین عدد پیدا‌شده هم اعلام شود» آن را هم می‌خواند. پس از آن هر تغییر تأییدشده اعلام می‌شود.

### نکات دقت

- OCR به فونت، وضوح، کنتراست، زبان و پوشیده نبودن عدد وابسته است. برای نشانه‌های گرافیکی از حالت تصویر استفاده کنید.
- مدل OCR پیش‌فرض ML Kit برای متون لاتین بهترین عملکرد را دارد. برای برچسب فارسی یا نمادی که خوانده نمی‌شود، حالت «تصویر نماد» انتخاب مطمئن‌تری است؛ ارقام فارسی/عربیِ خروجی نیز پیش از مقایسه نرمال می‌شوند.
- پنجرهٔ شناور را روی نشانه یا عدد قرار ندهید. اگر برنامهٔ مقصد اندازه/چرخش صفحه را عوض کرد، برای دقیق‌ترین نتیجه پایش را متوقف و دوباره شروع کنید.
- اندروید در هر شروع، رضایت تازهٔ کاربر برای Screen Capture می‌خواهد. برنامه هیچ‌گاه تلاش نمی‌کند این گفت‌وگو را دور بزند.

## پیش‌نیازها

- Android 8.0 (API 26) یا جدیدتر
- JDK 17 برای ساخت
- Android SDK Platform 35

## ساخت محلی

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleRelease
```

APK در این مسیر ساخته می‌شود:

```text
app/build/outputs/apk/release/
```

بدون تنظیم امضای release، خروجی عمداً `app-release-unsigned.apk` است. هیچ keystore یا رمز عبوری در مخزن نگه‌داری نمی‌شود. برای ساخت امضاشده:

```bash
./gradlew :app:assembleRelease \
  -PRELEASE_STORE_FILE=/absolute/path/to/release.keystore \
  -PRELEASE_STORE_PASSWORD='store-password' \
  -PRELEASE_KEY_ALIAS='key-alias' \
  -PRELEASE_KEY_PASSWORD='key-password'
```

## GitHub Actions: ساخت Release APK

فایل workflow در [`github-actions/android-release.yml`](github-actions/android-release.yml) نگه‌داری شده است تا بدون مجوز ویژهٔ GitHub Actions نیز بتوان پروژه را push کرد. برای فعال‌سازی، آن را دستی به `.github/workflows/android-release.yml` منتقل کنید؛ سپس با **Run workflow** از تب Actions اجرا می‌شود و APK را به‌عنوان artifact با نام `screen-number-watcher-release-apk` آپلود می‌کند. با push کردن تگ `v*` نیز APK را می‌سازد و در GitHub Release همان تگ قرار می‌دهد.

### امضای اختیاری در GitHub

اگر چهار Secret زیر را در **Settings → Secrets and variables → Actions** قرار دهید، workflow APK امضاشده می‌سازد:

| Secret | مقدار |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | فایل keystore به Base64، بدون قرار دادن فایل در Git |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | alias کلید |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

نمونهٔ تولید مقدار secret در Linux/macOS:

```bash
base64 -w 0 release.keystore
# macOS: base64 release.keystore | tr -d '\n'
```

اگر این Secretها تنظیم نشده باشند، workflow همچنان با موفقیت APK release **بدون امضا** را به artifact تبدیل می‌کند؛ برای نصب/انتشار عمومی آن را بعداً امضا کنید.

برای فعال‌سازی workflow، ابتدا این دستورها را اجرا کنید:

```bash
mkdir -p .github/workflows
mv github-actions/android-release.yml .github/workflows/android-release.yml
```

برای انتشار مبتنی بر تگ، پس از آماده بودن نسخه یک تگ مانند `v1.0.0` ایجاد و push کنید. workflow از Java 17، Gradle Wrapper، تست‌های واحد و `assembleRelease` استفاده می‌کند.
